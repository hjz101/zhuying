# 竹影阅读 3.0 兼容原型（阶段二）

端侧兼容引擎接入已有书源导入、搜索、详情、目录、阅读、缓存和生产书库。用户继续导入原版格式 JSON，无须改写成竹影 `json-v1`。导入与预览只解析配置和声明的主机，不执行脚本；用户主动发起登录、搜索、阅读或书源调试时才执行规则。

阶段二新增共享脚本作用域、登录表单与网页等待、动态多主机策略、内部请求引用、加密持久会话，以及按样本需要实现的加密和 Java 接口子集。它仍是兼容原型，不代表任意阅读 3.0 书源已可用。参考语义固定为 `gedoor/legado` 的 `fd026e0`；规则和宿主接口独立实现，没有复制 Android 应用代码。QuickJS 固定为官方 2026-06-04 版本，归档校验值见 `ios/Vendor/QuickJS/UPSTREAM.md`，MIT 声明随应用分发。

## 接入与结构

- `LegadoSourceDefinition` 读取原版搜索、详情、目录、正文、请求头、`jsLib`、登录等字段，验证必要配置。来源身份可以是字符串标识，实际请求主机由规则产生。
- `LegadoSourcePolicy` 通过词法扫描收集静态 HTTPS 候选主机，另接受用户在书源网络设置中明确添加的主机。候选列表不替规则选择线路，也不自动允许未知主机。
- `LegadoRuleEngine` 解析规则、模板、组合、替换和脚本片段。不对同步 `java.ajax` 做 `await` 文本替换；顺序执行的脚本保留中间值类型。
- `QuickJSScriptSession` 在来源会话的后台队列串行执行。库函数、库全局状态和显式 `globalThis` 状态可跨规则保留；每条规则的普通局部声明使用独立子作用域。请求绑定和宿主闭包逐次更新。
- `LegadoReference` 保留 HTTP／POST 请求描述和 `data:;base64` 内部载荷。`LegadoPersistentState` 隔离登录、变量、缓存、Cookie、允许主机和受保护的引用注册表。
- `LegadoBookSource` 继续实现现有 `BookSource` 协议。正式版复用原有书源、登录、搜索和阅读入口，不另设一套阅读页面。

## 来源身份、主机与凭据

不透明来源标识与网络地址分开保存。动态脚本必须先产生实际 HTTPS URL，再通过来源主机策略校验；没有静态起始 URL 时不会虚构一个网络 origin。未声明主机需要用户在书源网络设置中添加。HTTP 明文和跨主机重定向仍明确拒绝；多线路切换应由规则返回明确地址。

Cookie 按来源、账号、书库配置和请求主机隔离。来源级继承请求头绑定其主机；跨主机只继承 `Accept`、`Accept-Language`、`User-Agent`、`Content-Type` 等公开协商字段。规则在某次 URL 请求选项中明确设置的头按该次请求处理，不会因此自动复制其他主机的凭据。

带载荷、请求选项或查询参数的引用登记到受保护的注册表，书籍／章节元数据使用不透明引用键；阶段一已有的普通 HTTPS 直链仍兼容直接保存。完整 POST body 和私有请求头不进入书籍／章节元数据。已识别的 qingtian 载荷使用 `book_id`、`item_id`、`sources`、`tab` 等明确身份字段保持稳定，不随线路或标题修正改号。未知 HTTP 查询参数和 body 仍参与身份，不能猜测其中哪些字段是票据。注销不会删除引用注册表；旧会话票据需要重新获取，刷新后同一语义引用仍可映射到原键，阅读记录保留。

## 持久会话与网页登录

状态键包含来源、账号和当前书库配置。脚本变量与持久缓存整体使用 AES.GCM 加密的原子文件，随机密钥保存在钥匙串；登录信息、Cookie 和完整请求引用直接进入钥匙串快照。目录排除系统备份，这些凭据也不进入书源导出和书库普通备份。不能依赖字段名字判断敏感性，名为 `config` 的字符串同样加密。

内存缓存与带 TTL 的持久缓存分别处理。普通变量、缓存、引用和 Cookie 更新不会重置共享 JavaScript 作用域；登录信息实际改变、过期、注销或重置会使旧作用域失效。换凭据会清除旧 Cookie 和脚本缓存。注销保留允许主机与引用身份，但清除可能藏有票据的脚本变量／缓存；安装标识保持不变。

WebKit 数据存储同样包含来源、账号、书库配置和主机范围。打开网页前以受保护状态为准同步 Cookie，网页登录完成后以完整 Cookie jar 替换对应主机，避免已删除的旧 Cookie 被合并复活。网页返回不等于服务已验证账号；未验证状态允许实际请求，由服务响应确认可访问性，不能用任意 HTTP 200 或“登录成功”提示文字伪造认证结论。

## 明确边界

- 不运行 Android 界面、任意 Java／Rhino 对象或反射。`Packages.*` 仅限已实现的 Android Base64 对象；`JavaImporter` 的任意构造参数、其他 Java 类和硬件接口不支持。
- 不支持 HTTP 明文、任意跨主机重定向、音频／漫画书源或无限后台运行。多主机允许列表不等于允许自动跨主机复制凭据。
- 原生登录按钮和受限网页交互已接入；网页内部的同步 Android 宿主桥尚未实现。依赖它的内嵌设置页、验证流程可能明确报未支持。
- 依赖 `webJs`、正文独立 `replaceRegex`、`sourceRegex`、`payAction` 等高级字段时，对应步骤明确报未支持；已实现的规则内 `##` 替换继续可用。
- 不等同于完整 jsoup、Java 正则、XPath／JSONPath 或 Rhino 对象语义；少见复杂模板仍可能明确解析失败。Promise 和任意动态模块不作为同步宿主能力提供。
- 真实站点、账号权限、接口版本及线路可达性需要单独验收。端侧规则执行通过不能推导出参考 Android APK 行为完全一致。

## 运行限额

脚本默认预算 5 秒、16 MiB JS 堆、512 KiB 请求栈额度、128 次宿主调用、4 MiB 桥数据和 2 MiB 输出；实际可用栈还受后台线程限制。宿主重入最多 4 层，每操作最多 128 次脚本求值。普通操作默认 25 秒、最多 64 次网络请求／8 MiB 总响应，目录与正文默认最多 8 页，单字段最多 256 KiB；原生网络等待独立实现超时和取消。

已实现浏览器接口的等待时间不计入脚本与普通操作预算，浏览器交互自身默认等待 300 秒，仍支持取消／关闭／过期／注销，并保留调用与数据额度。普通网络等待没有这项豁免，不能用等待网页扩大网络或脚本执行额度。所有同步等待都在后台队列，主线程保持可用。

每来源账号的变量总量最多 512 KiB，持久缓存最多 128 项／512 KiB，Cookie 最多 256 个／256 KiB；内部引用注册表最多 4096 项／4 MiB 完整描述。单个内部载荷最多 128 KiB，完整引用最多 256 KiB。超过限额明确失败，不截断成另一条书籍／章节引用。
