# 步骤 0：性能与兼容基线（T005）

预算 v1 在首次测量和优化之前冻结于 `ios/YueshanTestSupport/performance-budget.json`。结果必须携带该文件的 SHA-256；更改预算需要新版本、理由及单独提交，不得根据测量值追改门槛。

## 冻结的负载与目标

| 项目 | 固定样本 | 目标上限 |
| --- | --- | --- |
| 书架排序 | 1000 本，最近／加入／书名排序 | 每次 150 ms |
| 长目录读取 | SQLite 中的 10000 章 | 每次 250 ms |
| 长书导入 | 1200 章，每章 8 段，每段至少 160 UTF-16 单元 | 每次 15000 ms |
| 书库恢复 | 上述长书及已保存的进度、收藏和偏好；重新打开数据库／文件仓库 | 每次 3000 ms |
| 本地切章读取 | 从文件仓库读取长书的一个未缓存章节 | 每次 100 ms |
| 长章生成正文 | 360 段，每段至少 280 UTF-16 单元，合计超过 10 万单元 | 每次 200 ms |
| 长章分页 | 同章、393 × 770 pt、20 pt 默认排版 | 每次 2000 ms |
| 旋转／大字号重排 | 同章、770 × 393 pt、30 pt | 每次 2000 ms |
| 基线进程峰值内存 | 独立性能测试宿主，Darwin ru_maxrss，MiB | 256 MiB |
| 正式空安装启动 | 从启动到原书架可用，单独 UI 测试 | 每次 3000 ms |

中文样本为自写测试文本，包含组合音标、扩展汉字、emoji 肤色／ZWJ／旗帜、阿拉伯文、英文、标点和数字。原有原创最小 TTF 字体及自包含 CSS／SVG 主题作为兼容样本；验证字体实际来源、缺失字体回退、浅深配色和标题样式，避免只测普通 ASCII。

## 测量规则

- 主机：Apple M4、16 GiB；Xcode 26.6（17F113）；专用 Yueshan Development QA，iPhone 17 Pro、iOS 26.5。版本与设备变化应另存基线。
- 使用 Debug 模拟器构建，覆盖现阶段开发路径；结果不代表 Release 真机速度。iOS 17 及真机的字体、旋转、内存和启动另行验收，不把编译通过写成运行通过。
- 计算与读取各取 5 次，完整导入与书库恢复各取 3 次；保留所有原始数值、中位数、最大值和目标比较，不把小样本叫作稳定的生产 P95。判定使用样本最大值。
- 每次存储测量使用独立临时目录；恢复采用新仓库实例，但 OS 文件页缓存可能仍命中，因此称“重新打开”，不声称磁盘冷缓存。
- 分页结果须连续覆盖全部原文，无重叠、缺尾或乱码；重排保持原文字锚点。时间测量不包含测试断言和样本生成。
- 内存读取的是独立测试宿主整个生命周期峰值，不是正文净增量，也不替代真机 Instruments 采样。
- 基线记录阶段保留未达目标项，明确指派 T015／T035 处理；T005 完成表示样本、方法、现状与目标冻结，不表示 T035 性能门槛已通过。测试仍必须验证样本、测量完整性和内容正确性，不允许用失败或缺失的测量冒充达标。

结果、命令和兼容矩阵在实际执行后追加于本文件；步骤 0 的 T003 真实书源结果另存，不能用这些原创样本替代。
