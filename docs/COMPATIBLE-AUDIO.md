# 自定义朗读与角色分析服务

适用正式模式 0.6.0。用户已选择自定义兼容服务，并在应用内自行配置。入口保持原 Demo 路径：我的 → 全部工具 → 朗读与声音 → AI 服务配置；阅读页 → 朗读 → 系统朗读／在线朗读／AI 多角色。未配置服务时系统朗读仍可独立使用，在线模式会提示配置，不会自动连接或播放。

## 配置与凭据

填写服务名称、HTTPS Base URL、TTS 模型、默认声音标识，以及需要时的角色分析模型。Base URL 可以包含 `/v1` 等路径，不允许账号、查询或片段。模型与声音由所选提供商支持，应用不预置收费提供商、试用密钥或自动购买流程。保存配置只保存；“测试已保存配置”会优先请求一段短测试语音并校验音频；只有分析模型时会请求原创短句的角色分析。测试可能消耗服务额度，但不会自动播放。

访问密钥只在应用 SecureField 内填写，保存到当前设备 Keychain，按配置及服务地址隔离；不在配置 JSON、日志、书源导出或原生备份中保存。不勾选“需要访问密钥”即可使用无密钥的自建服务。更换服务地址会清除旧凭据，替换／删除失败保留可恢复状态，并提供清理重试。App 内不回显已有密钥。只填写允许客户端使用的个人凭据；需要服务器保管的密钥由用户自己的兼容网关持有。

服务配置元数据和密钥均不进入阅山原生备份；恢复到其他设备后需重新配置服务。朗读偏好、保存的位置与角色声音映射随原生偏好备份。派生音频、分析结果缓存和主动下载正文均不属于原生备份内的本地导入正文。

## HTTP 接口

Base URL 下调用 `POST audio/speech`，Content-Type 为 JSON，需要鉴权时使用 Bearer 请求头：

```json
{"model":"用户配置的TTS模型","input":"当前短片段正文","voice":"用户配置的声音","speed":1.0,"response_format":"wav"}
```

返回 PCM RIFF/WAVE，支持 1／2 声道、8–192 kHz、16／24／32 bit PCM 或 32 bit 浮点。单片段上限 12 MiB。应用实际解码成功、底层输出确认开始后才显示播放；JSON 错误页、损坏音频和仅缓冲不视为播放。正文按句及 Unicode 边界分片，一次只预取下一片；完整校验当前片段后播放，不承诺边收边播任意服务器编码。HTTP 请求失败由用户继续当前片段，不自动重发可能收费的 POST。

角色分析调用 `POST chat/completions`，传入用户选择的模型、`stream:false`、`response_format:{"type":"json_object"}` 和 system／user messages。user 内容是带稳定片段 ID 的 `[{"id":"…","text":"…"}]`；读取 `choices[0].message.content` 中的 JSON：

```json
{"roles":[{"id":"narrator","name":"旁白"},{"id":"speaker-1","name":"陆青崖"}],"segments":[{"id":"输入的原始片段ID","role":"speaker-1"}]}
```

未知角色回退旁白；重复／外来片段 ID、错误结构拒绝保存。服务须支持上述子集，不能仅凭“兼容”名称确认可用。接口字段参考官方 [Speech](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create) 与 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 文档；本项目不要求使用该提供商。

## WSS 分片与续接协议

WSS 是阅山约定的显式协议，需要服务端支持，不能直接替代任意提供商的 WebSocket 地址。配置独立 `wss://` 地址。第一条消息包含 HTTP 语音参数（speed 为字符串），另有 `type:"synthesize"` 和唯一 `request_id`。服务按序发送 JSON 文本或 UTF-8 JSON 二进制消息：

```json
{"type":"audio","request_id":"原请求ID","sequence":0,"audio":"WAV字节片段的base64"}
{"type":"audio","request_id":"原请求ID","sequence":1,"audio":"后续WAV字节的base64"}
{"type":"done","request_id":"原请求ID"}
```

合并字节必须构成一份有效 WAV，不是把多份完整 WAV 拼接。最多 256 帧／12 MiB，整体超时 60 秒。网络断开时只重连一次，发送 `{"type":"resume","request_id":"原请求ID","from_sequence":下一序号}`，服务从该序号继续原合成。请求 ID 错误、重排／重复帧或服务不支持续接时停止并保留位置；不重新发起 synthesize。用户点击继续可能重新请求当前片段，是否收费由服务决定。

## 缓存、消耗与播放位置

音频以服务地址／配置、模型、声音、语速、正文版本和片段文本作为缓存键，校验内容哈希；最多 128 项／64 MiB。空间管理显示实际文件字节，可停止播放并清理派生音频，不删除本地作品、阅读进度或主动下载正文。

角色分析单章最多 40,000 个 UTF-16 单元，每批最多 6,000 单元；首次分析前先检查所需请求数。默认每次上限 8 个请求，可设 1–20；跨章自动分析默认关闭。分析缓存最多 30 章／8 MiB，正文或模型变化不复用旧结果；修改角色名及声音映射不重新分析。完整分析结果写盘失败时保留本次内存结果供重试保存，避免同一进程内重复付费；强退后无法保证未落盘结果恢复。

系统朗读提供当前系统实际可用声音、语速、暂停继续、跨章和正文跟随；声音不可用明确提示。手动阅读与朗读各自保存稳定位置，播放时单独计为朗读，不重复累计阅读。重启不自动播放；在线重启从保存的片段恢复，可能重放该片段。后台音频使用 iOS playback 会话和系统远程控制；中断及耳机拔出有状态保护，下载队列进入后台暂停，不承诺无限后台下载。

## 验收边界

当前自动化覆盖真实系统语音生成与播放，以及兼容接口契约、WAV 解码、断线续接、取消、错误响应、Keychain、缓存和角色模型。兼容服务的真实模型／声音／额度与长期跨章行为需用户在 App 配置后在线验收。真机锁屏、来电、耳机／蓝牙及签名内测尚无设备条件，模拟器测试不替代这些验收。
