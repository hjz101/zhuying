# iCloud 构建配置

当前未签名开发构建保持 iCloud 关闭，并在原生 iCloud 页面显示原因；用户已说明暂时无法提供真机与开发团队，不重复要求。原生传输与备份界面已接入，模拟传输模型不替代真实账号验收。

具备签名条件后，在 Xcode 对应用目标启用 iCloud Documents，容器与 `YueshanCloudContainer` 一致（默认 `iCloud.com.yueshan.reader`）。可参考 `ios/Yueshan/iCloud.entitlements.example`，由实际开发团队生成授权；在目标 Info 中设置布尔 `YueshanCloudEnabled=true`，并将签名权限文件配置为该团队实际可用容器。不要仅改布尔开关而省略授权。

完整备份使用该容器 `Documents/Yueshan/Backups`；记录日志保留在 `Records-v1`。备份在应用内下载校验、再次确认后恢复，旧书库保留为回滚代。上传状态由系统管理，文件写入成功不等于远端上传已完成。尚未下载的文件先请求系统下载，未就绪返回可重试状态。

传输每次检查当前账号，换账号会停止页面操作并清空待恢复对象；读取、写入使用 NSFileCoordinator，并支持取消。仍需在有授权的实际设备验证无账号、账号切换、断网、配额、后台上传、新设备下载与恢复。

## 记录同步

“iCloud → 记录同步”默认关闭。首次启用需要确认把当前书库与当前账号合并；账号切换会撤销开关和确认。启用后只在前台、退出阅读、书库可写时约每 30 秒检查，也可手动同步。同步期间停止朗读并锁住书库交互，元数据、目录、收藏顺序／分组、当前位置、最远文字位置、文字／媒体书签、媒体页位置与阅读偏好以一个 SQL 事务应用；失败回滚后重新载入原数据。

文字最远位置在每次确认阅读时单独保存，回读旧章不后退，不依赖下一次自动同步的采样。无书且未主动修改偏好的新设备，不发布默认偏好覆盖云端。正文和资源不通过记录同步传输，新设备缺失内容需恢复完整备份；目录与稳定位置仍保留。

采用设备向量版本、增量不可变日志和删除标记，不依据设备墙上时钟判新旧。并发删除优先；其他并发变化保留最多 8 个版本供页面选择，明确选择后产生新的因果版本。发布前持久化设备计数，上传后本地应用失败也不复用旧计数。超过 5000 条的首次目录拆分为多日志，单日志载荷 ≤ 5 MiB；读取 ≤ 8 MiB，最多 4096 个日志、50000 条记录、64 个设备，状态上限 32 MiB；超限在发布或应用前报错。删除标记不自动压缩清除，以免旧离线设备复活内容。

受控双设备传输已接实际 SQLite，测试覆盖同步后重启、正文不伪造、删除不复活、冲突选择、失效检查点、5001 条目录拆分，以及 SQL 应用失败回滚。当前无签名和实际账号条件，以上代码与测试不替代两台真实 iCloud 设备联调。
