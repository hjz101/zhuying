# 阅山：完整开发流程与任务清单

日期：2026-11-05。状态：用户已要求按本清单开发，并与 Demo 保持一致。范围、状态及证据见 [实施记录](IMPLEMENTATION-STATUS.md)。未勾选项仍待实施及验收。

依据：`ios/FEATURES.md` 的 47 项功能、`ios/QA.md` 各功能的最新验收记录、`docs/PRD.md` 的 AC-01～AC-19，以及当前原生工程。QA 是追加历史，后面的对应记录覆盖较早的实现边界。

## 1. 交付目标与优先级

首版目标：用户能导入自己的文字书，或从一个真实授权书源找到书，完成阅读、收藏、退出、重启和继续阅读；升级、网络失败、存储失败不破坏已有数据。现有排版、主题和字体成果继续使用并完成正式数据整合。

| 级别 | 安排 | 优先理由 |
| --- | --- | --- |
| P0 | 首版必做：真实内容、数据迁移、进度、阅读、基础书架、书签、近期缓存、本地备份及发布验证 | 直接决定是否能用、能否信任；也是其他能力的数据和交互基础 |
| P0-C | 条件成立时升级为首版必做：所选书源需要的服务端网关、网页登录 | 外部服务的访问条件决定依赖；不适用时必须留下验证证据才可跳过 |
| P1 | 第二版：多源、换源、EPUB、下载队列、全文索引、统计、系统朗读等 | 扩展日常价值，复用首版基础；可以按独立功能包交付 |
| P2 | 后续：在线与 AI 音频、iCloud、通用兼容引擎、其他媒体和高级设置 | 外部依赖或实现跨度大，需要独立的验证样本和验收边界 |

这里的级别是执行优先级。原 PRD 将缓存列为可选 P1；本方案建议把“近期缓存＋一章预取”纳入首版 P0，同时执行 AC-19；整本下载仍为 P1。书签、分组、本地备份也按上一轮建议纳入首版，T001 冻结范围时记录最终决定，改动时同步更新任务和发布门槛。

已有真实能力意味着“复用、拆分、迁移和复验”，而非重新制作全部界面。当前已有 TXT／文字 PDF 导入、正文、进度、排版、主题和字体；多源、登录、音频、备份、iCloud 等尚有模拟部分。正式构建不能把示例数据或可点击页面计作服务完成。

## 2. 完整流程与并行安排

推进顺序：范围与接口 → 三线开发 → 本地／在线分别联调 → 首版数据保障 → 真机内测与发布候选 → 按功能包扩展 → 全功能回归。

表格中的步骤表示依赖顺序，不要求做完一个步骤的所有任务再开始下一个步骤。每个任务以“前置”列为准；具备接口和测试替身后即可先开发，接真实存储或服务时必须再联调。

| 步骤 | 推进的功能 | 可并行工作 | 汇合点与用户可见结果 |
| --- | --- | --- | --- |
| 0 | 范围、测试基线、书源可行性、统一模型 | T002 测试基线、T003 书源验证、T004 数据接口可并行 | G0 冻结接口；G1 给出真实书源结论 |
| 1 | 数据库、文件归档、迁移、进度、偏好 | 数据线 A 主做；书源线 B、阅读线 C 按接口先开发 | 数据升级后书架、位置、字体和主题仍在 |
| 2 | 阅读会话、文字定位、排版手势、真实导入 | C 做阅读，D 做导入；A 继续提供仓库 | G2：本地导入→阅读→调整排版→重启恢复 |
| 3 | 真实搜索、详情、目录、正文、近期缓存 | B 做接口；A 做持久化；C 接阅读状态 | 网络闭环可用；失败不跳章、不覆盖进度 |
| 4 | 分组书签、备份恢复、清理、正式入口 | A 做备份；C 做入口；QA 连续验证 | G3：首版全流程、真机、内测反馈通过 |
| 5 | 多源换源、EPUB、下载、全文搜索、统计 | 内容线、格式线、音频线可按各自前置并行 | G4：第二版功能包各自通过，再做组合回归 |
| 6 | 系统／在线／AI 朗读 | 系统音频先行，在线与角色分析按依赖追加 | 系统朗读可先交付，不等待 AI |
| 7 | iCloud、规则兼容、媒体格式、高级工具 | 云同步、规则引擎、媒体三线可并行 | 依赖数据版本、正文定位、任务队列均已稳定 |
| 8 | 皮肤扩展、真实段评与全功能收口 | 皮肤可较早开发；段评先确认真实数据来源 | G5：完整功能按声明支持范围通过组合回归 |

推荐工作线按职责划分，不预设已经配备对应人数：

| 工作线 | 可以一起推进的任务 | 开始条件 | 需要协调的共享部分 |
| --- | --- | --- | --- |
| A 数据与可靠性 | T006～T012、T031～T033 | T004 接口完成后 | 数据库迁移由一个负责人串行编号；文件与数据库提交协议共用 |
| B 书源与网络 | T003、T021～T030 | 验证可先行；正式适配需 G0、G1 | DTO、稳定书源标识、错误类型、凭据边界 |
| C 阅读与外观 | T013～T016、T018、T034 | T004 和测试替身可用后 | 只维护一份定位协议、正文变换流程和有效阅读样式 |
| D 导入与格式 | T017、T019，随后 T042、T061～T064 | T004 可先开发解析；落库依赖 A | 与 C 对齐统一文档；PDF 原版式和漫画使用各自定位模型 |
| E 验证与发布 | T002、T005、每项验收、T035～T038 | 从项目开始持续进行 | 每条开发线都交测试；集中整理真机矩阵和发布证据 |
| F 音频与同步 | T049～T056 | 音频依赖稳定定位；同步依赖稳定存储与备份 | 播放／阅读位置、后台生命周期、记录版本及冲突策略 |

两人时建议一人负责数据＋阅读，另一人负责书源＋导入；接口冻结后交叉联调。三人时拆为数据、阅读／导入、书源；测试由各人随功能完成。只有一人时仍按依赖顺序切换任务，书源等待资料期间推进本地工作，不同时打开多个未完成的大改造。

数据库迁移、全局模型、阅读定位协议、导入提交协议需要单一负责人合并。迁移和云同步、正文净化和排版、换源和进度恢复不能各自改变协议后直接合并。远端缺少资料时只阻塞依赖它的任务；在线版仍必须满足真实联调门槛。

## 7. 每个任务的执行闭环与排期方式

每次只领取前置已满足的任务：确认范围和样本 → 编写／更新相关测试 → 实现一个可审阅的改动 → 运行受影响测试和检查 → 必要的联调／真机验证 → 保存证据 → 创建对应 Git commit → 更新任务状态。大型任务继续拆成有测试、可回滚的提交；不能只在最后整体补测试。

任务完成记录至少包括：负责人、开始／结束日期、实现范围、测试命令与结果、真机／服务证据、commit、限制和遗留问题。接口阶段使用假实现的测试通过，只代表契约通过；真实服务与最终 UI 验收另记，不互相替代。

建议状态流：未开始 → 进行中 → 待联调／待资料 → 待验收 → 完成。阻塞项写明缺少资料、影响任务和替代工作；状态变化后更新本文件。勾选完成意味着相关测试和验收已通过，不表示仅完成编码。

全量界面回归放在 G3／G4／G5 前；日常变更运行相关模型测试与受影响 UI 路径。新增文件结构或工程配置时检查 Xcode 工程；本次只有规划文档变更，使用规划一致性测试与现有网页检查，不把历史 iOS 测试记录当成本次重跑。

首版工作量在 T003、T004、T005 完成后按任务估算，再按人数和并行依赖换算日历。上一轮 6～10 周只是“一名熟悉工程的 iOS 开发者、必要后端支持、书源可用”的粗排占位；本清单不将其扩展成全部 47 项的承诺。优先估出数据迁移、阅读定位、真实源、备份、真机这五项，再安排缓冲。每周至少交付一条可演示、可测试的功能路径。

第一批领取顺序：T001；随后 T002／T003／T004 并行；T004 完成后 A 线启动 T006，C 线启动 T013，D 线启动 T017；T003 完成后 B 线启动 T021；T002 与 T004 完成后执行 T005。第一批目标是验证真实源、冻结接口并让三条主线具备开发条件。
