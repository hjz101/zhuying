# 竹影阅读 3.0 兼容原型（阶段三）

端侧兼容引擎接入已有书源导入、搜索、详情、目录、阅读、缓存和生产书库。用户继续导入原版格式 JSON，无须改写成竹影 `json-v1`。导入与预览只解析配置和声明的主机，不执行脚本；用户主动发起登录、搜索、阅读或书源调试时才执行规则。

阶段二提供共享脚本作用域、登录表单与网页等待、动态多主机策略、内部请求引用、加密持久会话，以及按样本需要实现的加密和 Java 接口子集。阶段三补充进程级脚本预留总预算、操作租约与空闲回收、书籍净化开关、稳定资料库身份，以及结构化安全诊断和跨进程验收证据。它仍是兼容原型，不代表任意阅读 3.0 书源已可用。参考语义固定为 `gedoor/legado` 的 `fd026e0`；规则和宿主接口独立实现，没有复制 Android 应用代码。QuickJS 固定为官方 2026-06-04 版本，归档校验值见 `ios/Vendor/QuickJS/UPSTREAM.md`，MIT 声明随应用分发。

## 接入与结构

- `LegadoSourceDefinition` 读取原版搜索、详情、目录、正文、请求头、`jsLib`、登录等字段，验证必要配置。来源身份可以是字符串标识，实际请求主机由规则产生。
- `LegadoSourcePolicy` 通过词法扫描收集静态 HTTPS 候选主机，另接受用户在书源网络设置中明确添加的主机。候选列表不替规则选择线路，也不自动允许未知主机。
- `LegadoRuleEngine` 解析规则、模板、组合、替换和脚本片段。不对同步 `java.ajax` 做 `await` 文本替换；顺序执行的脚本保留中间值类型。
- `QuickJSScriptSession` 在来源会话的后台队列串行执行。库函数、库全局状态和显式 `globalThis` 状态可跨规则保留；每条规则的普通局部声明使用独立子作用域。请求绑定和宿主闭包逐次更新。
- `QuickJSScriptMemoryBudget` 按各 VM 的配置堆上限预留全进程额度；`withLease` 固定整个来源操作使用的 VM，空闲 VM 才参与 LRU 或内存压力回收。
- `LegadoReference` 保留 HTTP／POST 请求描述和 `data:;base64` 内部载荷。`LegadoPersistentState` 隔离登录、变量、缓存、Cookie、允许主机和受保护的引用注册表。
- `LegadoLibraryProfileIdentity` 为当前资料库保存稳定 UUID。`SourceDiagnostics` 和 `SourceAcceptanceRunner` 在原调试入口生成分类结果与脱敏验收记录，实际网络计数由独立原生 transport 提供。
- `LegadoBookSource` 继续实现现有 `BookSource` 协议。正式版复用原有书源、登录、搜索和阅读入口，不另设一套阅读页面。

## 来源身份、主机与凭据

不透明来源标识与网络地址分开保存。动态脚本必须先产生实际 HTTPS URL，再通过来源主机策略校验；没有静态起始 URL 时不会虚构一个网络 origin。未声明主机需要用户在书源网络设置中添加。HTTP 明文和跨主机重定向仍明确拒绝；多线路切换应由规则返回明确地址。

Cookie 按来源、账号、书库配置和请求主机隔离。来源级继承请求头绑定其主机；跨主机只继承 `Accept`、`Accept-Language`、`User-Agent`、`Content-Type` 等公开协商字段。规则在某次 URL 请求选项中明确设置的头按该次请求处理，不会因此自动复制其他主机的凭据。

带载荷、请求选项或查询参数的引用登记到受保护的注册表，书籍／章节元数据使用不透明引用键；阶段一已有的普通 HTTPS 直链仍兼容直接保存。完整 POST body 和私有请求头不进入书籍／章节元数据。已识别的 qingtian 载荷使用 `book_id`、`item_id`、`sources`、`tab` 等明确身份字段保持稳定，不随线路或标题修正改号。未知 HTTP 查询参数和 body 仍参与身份，不能猜测其中哪些字段是票据。注销不会删除引用注册表；旧会话票据需要重新获取，刷新后同一语义引用仍可映射到原键，阅读记录保留。

## 持久会话与网页登录

状态键包含来源、账号和当前资料库的稳定 UUID，Demo 与正式资料库使用各自命名空间。UUID 随资料库的身份文件保留，应用升级造成容器路径变化时继续使用同一身份；绝对安装路径及备份代际目录不再作为当前资料库身份。脚本变量与持久缓存整体使用 AES.GCM 加密的原子文件，随机密钥保存在钥匙串；登录信息、Cookie 和完整请求引用直接进入钥匙串快照。目录排除系统备份，这些凭据也不进入书源导出和书库普通备份。不能依赖字段名字判断敏感性，名为 `config` 的字符串同样加密。

历史版本曾把绝对路径放进资料库 namespace。只有掌握完整旧 scope（来源、账号、旧资料库 namespace）并能验证其加密文件及钥匙串关联时，才可把该作用域迁到新 UUID；目标已存在独立状态时拒绝覆盖。迁移保留原数据。无法证明完整旧 scope 时，保留原文件并要求重新登录，不根据文件数量、修改时间或“最新文件”猜测归属，也不尝试把其他来源或账号的数据关联过来。

内存缓存与带 TTL 的持久缓存分别处理。普通变量、缓存、引用和 Cookie 更新不会重置共享 JavaScript 作用域；登录信息实际改变、过期、注销或重置会使旧作用域失效。换凭据会清除旧 Cookie 和脚本缓存。注销保留允许主机与引用身份，但清除可能藏有票据的脚本变量／缓存；安装标识保持不变。

WebKit 数据存储同样包含来源、账号、书库配置和主机范围。打开网页前以受保护状态为准同步 Cookie，网页登录完成后以完整 Cookie jar 替换对应主机，避免已删除的旧 Cookie 被合并复活。网页返回不等于服务已验证账号；未验证状态允许实际请求，由服务响应确认可访问性，不能用任意 HTTP 200 或“登录成功”提示文字伪造认证结论。

## 明确边界

- 不运行 Android 界面、任意 Java／Rhino 对象或反射。`Packages.*` 仅限已实现的 Android Base64 对象；`JavaImporter` 的任意构造参数、其他 Java 类和硬件接口不支持。
- 不支持 HTTP 明文、任意跨主机重定向、音频／漫画书源或无限后台运行。多主机允许列表不等于允许自动跨主机复制凭据。
- 原生登录按钮和受限网页交互已接入；网页内部的同步 Android 宿主桥尚未实现。依赖它的内嵌设置页、验证流程可能明确报未支持。
- 依赖 `webJs`、正文独立 `replaceRegex`、`sourceRegex`、`payAction` 等高级字段时，对应步骤明确报未支持；已实现的规则内 `##` 替换继续可用。
- 不等同于完整 jsoup、Java 正则、XPath／JSONPath 或 Rhino 对象语义；少见复杂模板仍可能明确解析失败。Promise 和任意动态模块不作为同步宿主能力提供。
- 真实站点、账号权限、接口版本及线路可达性需要单独验收。端侧规则执行通过不能推导出参考 Android APK 行为完全一致。

## 运行限额

每个 VM 默认 16 MiB JS 堆。全进程 QuickJS 默认 96 MiB 预留总预算，按活跃及空闲 VM 的配置堆上限累计；默认配置最多保留六个 VM 的额度。这是配置上限预留，不测量实际 JS 用量，也不是进程 RSS、原生网络缓冲或 WebKit 内存的总上限。预算满时先回收最近最少使用的空闲 VM，没有空闲 VM 时后台有界等待，支持超时、取消和重置；VM 真正销毁后才归还额度。整个来源操作持有租约，操作内多次规则求值及受控等待期间不回收该 VM。系统内存压力或 UIKit 内存警告会在后台回收空闲 VM，活跃 VM 在租约结束后处理。回收后下一次调用重新加载库与持久宿主状态，未写入宿主存储的临时 JS 全局值不会永久保留。

脚本默认执行预算 5 秒、512 KiB 请求栈额度、128 次宿主调用、4 MiB 桥数据和 2 MiB 输出；实际可用栈还受后台线程限制。5 秒统计解释器及普通宿主执行的耗时，不是进程 CPU 时间。受控 `java.ajax`／`get`／`post`／`head`／`connect` 原生 HTTP 等待从该预算中排除，脚本参数序列化、请求前后代码、普通宿主计算及调用／数据额度仍受限制。宿主重入最多 4 层，每操作最多 128 次脚本求值。

普通操作默认 25 秒墙钟上限，最多 64 次网络请求／8 MiB 总响应；单次请求继续受自身超时、取消及操作剩余墙钟预算约束。HTTP 等待不延长这 25 秒。目录与正文默认最多 8 页，单字段最多 256 KiB。

已实现浏览器接口的用户等待另有默认 300 秒上限，等待期间暂停脚本执行预算和普通操作墙钟预算，仍支持取消／关闭／过期／注销，并保留调用与数据额度。该交互等待与普通 HTTP 等待分别处理，不能借浏览器接口放宽后续请求额度。所有同步等待都在后台队列，主线程保持可用。

每来源账号的变量总量最多 512 KiB，持久缓存最多 128 项／512 KiB，Cookie 最多 256 个／256 KiB；内部引用注册表最多 4096 项／4 MiB 完整描述。单个内部载荷最多 128 KiB，完整引用最多 256 KiB。超过限额明确失败，不截断成另一条书籍／章节引用。

## 安全诊断与完整验收

“书源调试”继续使用原配置卡、分步结果和导航路径。失败行显示固定分类与恢复动作，不显示原始 JavaScript 异常、完整脚本或 HTTP 负载。普通分步调试也不会把原生请求全部失败后返回的缓存正文记为成功。保存账号输入、网页完成或 HTTP 200 均不会自动标记登录已验证；调试结果不能替服务确认账号权限。

完整验收对书名和作者规范化后去重，两条不同来源记录不能仅凭不同 `book.id` 算作两部作品。首次检查至少两部不同作品、每部三个可读章节，搜索及每章正文都需在本次步骤取得原生成功请求计数。仅目录成功、持久缓存命中或非空正文不足以替代逐章联网证据。记录包括每步成功／失败请求数和字节数、来源／作品／章节身份哈希及正文版本指纹；不保存查询词、正文、密码、Cookie、token、请求 body 或完整脚本。

检查点按来源、账号、稳定资料库身份隔离，同时绑定配置哈希、认证会话代际哈希及验收引擎版本。首次完成只标记“等待真正重启”；同一应用进程不能完成重启复核。真正终止并重启应用后，要重新检索同一组作品、章节并逐章联网核对指纹，才能生成跨进程复核结果。配置或账号会话变化、内容不一致、步骤失败、缺少当次成功请求、证据不足、取消或超时均不产生通过结论。检查点读取先验证普通文件、符号链接及大小，恢复时验证步骤与计数；导出的脱敏 JSON 可供后续工具对照，但不等于已执行 Android APK 差分。

这类记录证明已检查的规则返回与原生请求，不证明全部作品、未覆盖线路或所有脚本能力均兼容。即使 HTTP 返回 200，业务错误仍须由原规则或原生错误明确识别，不能仅靠非空字符串判定真实站点全链路可读。
