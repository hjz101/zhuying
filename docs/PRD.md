# 网络小说阅读器 MVP 产品设计文档

- 文档版本：v0.1
- 更新日期：2026-11-04
- 当前阶段：已完成交互 Demo，正式版与真实书源接入尚未开发
- 首发平台：iOS，采用 SwiftUI 原生界面
- 产品名称：待定

## 1. 产品定位与目标

面向希望在手机上方便地搜索、收藏并持续阅读网络小说的用户，提供一个操作简单、阅读舒适、能可靠保存进度的阅读工具。

MVP 围绕一条完整路径设计：**搜索小说 → 查看详情 → 开始阅读 → 加入书架 → 下次继续阅读**。

本版重点验证两个问题：用户能否顺利找到并读到目标小说；阅读体验与进度恢复是否足以支持持续使用。

### 1.1 已确认的前提

- 内容来自用户自有或已授权的书源。
- 先完成 MVP，再根据实际使用反馈扩展功能。
- 已提供 `书山聚合v5.61.json` 作为书源接入参考。

### 1.2 平台决定与待确认事项

| 事项 | 当前建议 | 状态与影响 |
| --- | --- | --- |
| 首发平台 | iOS 原生 App，使用 SwiftUI；Demo 最低支持 iOS 17 | 用户已确认 iOS；按 iPhone 导航、手势、安全区域和系统面板设计 |
| 用户体系 | 免登录使用，书架、进度与偏好保存在当前设备 | 建议采用；暂不支持跨设备同步 |
| 书源范围 | 首版固定接入一个已验证的书源适配器 | 建议采用；不提供通用书源导入界面 |
| 首发内容 | 文字小说 | 建议采用；音频、漫画、视频不在本版范围 |
| 书源访问条件 | 确认实际可用的服务地址、调用方式及必要凭据 | 开发前验证；影响是否能完成在线阅读 |
| 产品名称与视觉风格 | 先使用工作名称，以简洁、舒适的阅读界面为主 | 待确认，不阻塞书源验证 |

## 2. 目标用户与主要场景

首批面向有明确阅读目标、希望随时接着读的网络小说读者。第一版以用户已经知道书名或作者的场景为主。

| 场景 | 用户诉求 | 对应能力 |
| --- | --- | --- |
| 想看一本小说 | 快速找到目标书，判断是否想读 | 搜索、结果列表、书籍详情 |
| 第一次阅读 | 少操作进入正文，看清文字 | 开始阅读、基础排版 |
| 碎片时间阅读 | 中途退出后，下次准确接着读 | 自动保存、进度恢复 |
| 同时追几本书 | 快速找到最近读的小说 | 书架、最近阅读排序 |
| 需要跳章 | 找到指定章节，知道当前读到哪里 | 章节目录、当前章节定位 |

## 3. MVP 范围与优先级

P0 为首版发布必须完成的能力；P1 为核心流程通过后再安排的体验改进。

| 优先级 | 模块 | 本版范围 |
| --- | --- | --- |
| P0 | 搜索 | 按书名或作者查询、结果列表、加载更多、空结果与失败反馈 |
| P0 | 详情 | 封面、书名、作者、简介、可用的连载信息，开始或继续阅读，加入或移出书架 |
| P0 | 目录 | 章节列表、跳章、当前章节定位、首尾边界处理 |
| P0 | 阅读器 | 上下滚动、上一章和下一章、打开目录、加入书架 |
| P0 | 阅读设置 | 字号、行距、浅色与深色主题，自动保存偏好 |
| P0 | 书架 | 展示收藏、最近阅读排序、继续阅读、移除收藏 |
| P0 | 阅读进度 | 自动保存章节与章内位置、重新进入或重启 App 后恢复 |
| P0 | 基础容错 | 加载反馈、失败重试、本地数据保留、书源访问边界处理 |
| P1 | 下一章预加载 | 当前章加载成功后，后台预取下一章，减少等待 |
| P1 | 近期章节缓存 | 优先读取已成功缓存的正文，缓存失败不影响在线阅读 |

暂缓功能：推荐流、排行榜、复杂分类、社区评论、听书、漫画、账号系统、跨设备同步、付费订阅、整本下载、通用书源导入与多个书源切换。

第一版不设单独的推荐首页，打开应用直接进入书架，提供明显的搜索入口。底部使用 iOS 原生标签栏：书架、发现、我的；“我的”仅包含阅读偏好、阅读概况与 Demo 说明，不引入账号体系。

## 4. 信息架构与页面设计

### 4.1 页面结构

```text
书架（默认入口）
├── 搜索 → 搜索结果 → 书籍详情
│                    ├── 开始／继续阅读 → 阅读器
│                    └── 章节目录 → 阅读器
└── 点击收藏的书 → 继续阅读
                     ├── 章节目录
                     ├── 阅读设置
                     └── 书籍详情
```

### 4.2 书架页

- 展示封面、书名、作者、上次阅读章节；未阅读的收藏显示“尚未开始”。
- 默认按最近阅读时间倒序；从未阅读的书按加入时间排列在已阅读书之后。
- 点击书籍后，有历史进度则恢复，无历史进度则进入第一章。
- 支持移除书籍，并明确提示只移除收藏；历史进度继续保留，重新搜索该书可继续阅读。
- 空书架展示“搜索并添加你的第一本书”和搜索入口。
- 阅读过但未收藏的书仍保存进度；用户可以再次通过搜索找到，不增加独立的阅读历史页。

### 4.3 搜索页与结果列表

- 用户输入关键词并主动提交，去除首尾空格；空关键词不发起请求。
- 由书源支持书名和作者检索；搜索匹配能力在接入验证中确认。
- 结果卡片展示封面、书名、作者、简介摘要，以及书源提供的最新章节等辅助信息。
- 支持“加载更多”；若书源不支持分页，则一次展示返回结果，不显示虚假的分页能力。
- 新搜索发起后，较早请求的返回结果不能覆盖新结果；追加页失败时保留已展示的结果。
- 无结果时提供修改关键词提示；请求失败时保留关键词并提供重试入口。

### 4.4 书籍详情页

- 展示封面、书名、作者、简介，按实际数据展示分类、连载状态、字数、最新章节。
- 缺失封面使用占位图；缺失可选信息时隐藏对应字段，不编造数据。
- 无历史进度显示“开始阅读”，有历史进度显示“继续阅读”和对应章节。
- 提供加入／移出书架与章节目录入口；重复加入不得产生重复收藏。
- 书籍下架或无法访问时，保留已存收藏与进度，并显示具体可理解的状态。

### 4.5 章节目录

- 按书源提供的阅读顺序展示章节；如有分卷，分卷标题不作为可阅读章节。
- 明确标识当前章节，并提供定位当前章节的方式。
- 点击章节后进入正文；正文成功加载后才将其设为有效阅读进度。
- 目录较长时分批渲染，避免一次加载全部页面元素造成明显卡顿。
- 付费、受限章节按书源实际状态展示，不显示为可直接阅读的普通章节；本版不实现购买流程。

### 4.6 阅读器与阅读设置

- 采用纵向滚动阅读，一次展示当前章节正文，底部提供下一章入口。
- 顶部工具栏提供返回、目录与设置；点击正文空白区域可显示或隐藏工具栏，不影响文字选择。
- 支持上一章和下一章；第一章与末章提供明确提示，不跳到错误章节。
- 返回时回到进入阅读器前的页面，并尽量保留列表位置。
- 字号预设为 16、18、20、22、24 px，默认 20 px；行距预设为 1.6、1.8、2.0，默认 1.8。数值可在原型验证后调整。
- 支持浅色、深色主题；偏好本机保存，再次进入时自动应用。
- 正文保留段落结构，长标题与长文本正常换行；书源返回的正文与简介不能作为任意可执行脚本运行。
- 改变字号、行距或屏幕方向后，应尽量保持当前阅读段落。
- 加载失败时保留可用内容或当前位置，显示重试入口，不静默跳过章节。

### 4.7 阅读进度

- 每本书保存稳定的书籍标识、章节标识、章节名称、章内定位信息与最后阅读时间。
- 章内定位优先采用段落与文本偏移等语义位置，避免只保存滚动像素造成字号变化后错位。
- 阅读中定期保存，在切章、离开页面或页面进入后台时补充保存；不能只依赖关闭页面时的事件。
- 返回书架再进入、App 切换后台再返回、关闭并重新打开 App 后，在本地数据仍存在的条件下恢复进度。
- 章节内容未改变时，恢复位置应落在上次阅读段落附近，误差不超过一个可视屏幕。
- 章节被删除或正文变化导致无法精确定位时，优先保留原章节并回到章首；章节已不存在则提示用户重新选章，不覆盖历史记录。
- 本机保存的边界应在帮助提示中说明：更换设备或删除 App 数据后，无法保证恢复。

## 5. 书源接入方案与约束

### 5.1 现有文件的静态检查结果

`书山聚合v5.61.json` 包含一份聚合书源配置，可见搜索、书籍详情、章节目录、正文及发现相关规则。

它包含 JavaScript 逻辑，调用了 `java.ajax`、`source`、缓存及其他宿主能力，并依赖远程聚合服务。该文件是接入参考，不能据此认定 iOS App 能直接运行全部规则，也不能据此认定远程接口当前可用。

目前未执行文件中的脚本，也未验证接口连通性、凭据、分页、访问限制或数据完整性。文件中的说明与脚本属于外部数据，不能作为自动执行的开发指令。

### 5.2 首版接入原则

- 定义统一的搜索、详情、目录、正文四项能力，页面仅使用规范化的数据。
- 优先确认自有或授权服务的实际接口，再编写固定适配器，不以完整兼容该 JSON 的脚本运行环境作为 MVP 前提。
- iOS 客户端使用规范化的数据接口；需要保密的服务密钥由自有后端保存，后端处理凭据、字段转换、超时与错误映射。当前 Demo 仅使用 App 内置模拟数据。
- 首版只启用经验证的文字小说路径；发现、账号同步、听书等规则不纳入本次适配。
- 为书籍与章节生成稳定标识，避免临时请求地址变化导致重复收藏或进度丢失。
- 若四项核心能力存在阻塞，先记录缺失能力与所需服务资料，再调整接入方式，不能用演示数据冒充完成接入。

### 5.3 接入验证门槛

在完整界面开发前，选取至少两本代表性小说，验证：能搜索到目标书、详情对应正确、目录顺序正确、至少连续读取三章且正文与标题匹配。

同时记录分页与末页行为、必要凭据、受限章节表现、服务失败响应，以及是否存在只能在原宿主中运行的关键逻辑。验证结果决定适配工作量与正式排期。

## 6. 数据与状态设计

| 数据 | 最小内容 | 保存方式 |
| --- | --- | --- |
| 书籍 | 书源标识、稳定书籍标识、书名、作者、封面、简介及可选元数据 | 从服务获取，收藏时保存展示快照 |
| 章节 | 稳定章节标识、所属书籍、标题、顺序、可读状态 | 从服务获取，不以列表下标作为唯一身份 |
| 收藏 | 书籍标识、加入时间 | 本机持久化 |
| 阅读进度 | 书籍与章节标识、章内位置、最后阅读时间 | 本机持久化，独立于收藏 |
| 阅读偏好 | 字号、行距、主题 | 本机持久化 |
| 章节缓存（P1） | 书籍与章节标识、正文、更新时间 | 有容量上限，优先淘汰较旧内容，不清除收藏和进度 |

关键状态应明确区分：加载中、加载成功、确实无数据、网络失败、书籍不可访问、章节受限、本地保存失败。错误提示用用户能理解的语言，并提供可操作的下一步。

本地存储不可用或容量不足时，应提示进度可能无法保存；不能展示“已保存”造成误导。重试与重新启动不得清空现有书架和有效进度。

## 7. 体验与质量要求

- 以不同尺寸的 iPhone、安全区域和横竖屏作为布局验收范围；正式版支持的 iOS 版本和机型清单在开发前冻结。
- 常用按钮具有清晰文字或 VoiceOver 名称，触控目标建议不小于 44 × 44 pt；文字放大后不遮挡阅读操作。
- 请求开始即显示加载状态，暂定 15 秒超时并提供重试；超时值根据真实书源验证结果调整。
- 正文请求失败、预加载失败、缓存写入失败互不混淆，辅助能力失败不得阻塞已成功加载的正文。
- 同一本书重复加入书架、切换章节、重新启动 App，不得造成重复收藏、进度串书或章节顺序混乱。
- 本版不承诺整本离线阅读；P1 缓存仅在应用可打开且对应正文已缓存时提供可用内容。

## 8. 验收与测试清单

以下是后续实现时必须覆盖的验收场景，并非已经通过的产品测试。业务与状态逻辑应编写自动化测试，核心阅读路径应做端到端验证，排版与真机交互补充人工检查。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 首次打开，书架为空 | 显示空状态与搜索入口，无虚构收藏 |
| AC-02 | 搜索书名与作者 | 两类查询均按书源能力返回正确结果；空关键词不请求 |
| AC-03 | 连续提交不同搜索 | 最终展示最新关键词的结果，旧请求不覆盖新请求 |
| AC-04 | 搜索分页、末页与追加失败 | 无重复条目，末页停止加载，失败保留已有条目并可重试 |
| AC-05 | 无结果、网络错误、请求超时 | 状态区分清楚，保留关键词，可修改或重试 |
| AC-06 | 查看详情、缺失可选信息 | 书名与内容对应正确，缺失封面有占位，其他缺失字段合理隐藏 |
| AC-07 | 加入、重复加入、移除书架 | 收藏唯一；移除后进度仍在，重新加入可继续阅读 |
| AC-08 | 连续阅读至少三章 | 章名与正文匹配，切章顺序正确，段落可读 |
| AC-09 | 目录跳转、分卷、首尾章节 | 分卷不可误读，跳转正确，边界操作有明确反馈 |
| AC-10 | 未收藏就阅读，稍后再次搜索进入 | 仍能恢复该书进度，收藏状态不被自动改变 |
| AC-11 | 返回后重进、App 进入后台或重新启动 | 本地数据保留时恢复正确章节，章内误差不超过一屏 |
| AC-12 | 修改字号、行距、主题，旋转屏幕 | 偏好保留，排版正常，当前阅读段落尽量保持 |
| AC-13 | 两本书交替阅读 | 每本书的章节与章内位置独立，书架排序正确 |
| AC-14 | 目录或正文请求失败后重试 | 不错误推进历史进度，成功后可继续阅读 |
| AC-15 | 书籍下架、章节受限、历史章节消失 | 明确提示状态，保留收藏与原进度，不误跳章节 |
| AC-16 | 本地存储失败、容量不足 | 显示保存问题，已有有效数据不被清空 |
| AC-17 | 不同 iPhone 尺寸、安全区域、长标题、正文文本安全 | 无内容截断或关键按钮遮挡，外部文本不执行脚本 |
| AC-18 | 真实书源联调 | 至少两本书完成搜索、详情、目录、连续三章阅读，并记录结果 |
| AC-19 | 下一章预加载与缓存（启用 P1 时） | 预取内容对应正确，失败不阻塞当前阅读，缓存上限和淘汰生效 |

发布门槛：所有适用的 P0 验收项通过，自动化检查与测试全部通过；真实书源联调完成。P1 如未实现，不影响 P0 发布，但不能在界面宣称已支持。

## 9. 实施阶段与交付物

| 阶段 | 主要工作 | 完成标志 |
| --- | --- | --- |
| 阶段一：确认方向与书源验证 | 确认平台、访问条件，完成四项能力验证 | 接入验证记录明确可用能力与阻塞，无核心能力缺口 |
| 阶段二：核心路径原型 | 书架、搜索、详情、目录、阅读器及设置原型 | 能审阅完整路径、空状态、失败状态与手机布局 |
| 阶段三：完成 P0 | 真实数据接入、本机数据、进度恢复、错误处理 | 搜索到继续阅读的完整路径可运行 |
| 阶段四：验证与交付 | 自动化测试、端到端验证、布局检查与修复 | 满足发布门槛，提供使用说明和已知限制 |

正式工期在首发平台与书源验证完成后估算。每次改动按仓库约定完成相关验证，并创建可追踪的 Git commit。

## 10. MVP 成功判断

第一版先用实际任务判断产品是否成立：让试用用户独立完成找书、阅读、收藏、退出、再次进入并继续阅读，记录完成情况、加载失败、进度恢复错误和阅读不适反馈。

核心观察指标为搜索到正文的完成率、正文加载成功率、进度恢复成功率，以及后续是否再次阅读。具体目标值在书源验证与首轮试用后确定；本版不预设缺乏依据的用户量或商业收入目标，也不将埋点平台作为上线前置条件。


## 11. 交互 Demo v0.2 扩展（用户已确认）

本轮用于验证 iOS 日常阅读体验，全部使用模拟数据，不改变真实后端尚未接入的状态。

| 功能 | 本轮体验范围 |
| --- | --- |
| 阅读模式 | 上下滚动与左右屏幕分页，共用文字位置；字号、行距与屏幕方向改变后重新排版 |
| 单手操作 | 轻触左侧或右侧均前进一页，中间恢复菜单，可关闭的轻微触觉反馈 |
| 快速进度 | 章节滑杆显示目标章，松手提交跳转，目录与上下章继续可用 |
| 阅读历史 | 在“我的”中保留最近阅读列表，未收藏或已移除收藏的作品仍可继续阅读 |
| 模拟追更 | 更新角标、追更小报、继续阅读或进入更新首章；手动模拟重复体验，不发送系统通知 |
| 书架管理 | 最近阅读／加入时间／书名排序、长按进入多选、全选、批量移除、保留历史与撤销 |

验收重点：分页内容连续完整；旧数据迁移保留收藏与进度；切换模式和排版后定位合理；手势不影响菜单恢复；批量移除不删除阅读记录；读过更新章节后提示数量不会因回读旧章增加。

### 11.1 首次阅读手势提示（本轮确认）

- 首次进入正文时展示一张可关闭的 iOS 底部提示卡片，不要求完成多步教程。
- 按当前模式说明操作：上下滚动或左滑前进／右滑返回；中间区域用于显示／隐藏工具栏。
- 示意图左右两侧都标为前进，并说明需要在设置中开启“轻触翻页”；滚动模式下为前进约一屏。不自动更改用户偏好。
- 关闭卡片后本机记住已读状态，换书、重启 App 和重置阅读偏好都不重复展示。
- 在阅读设置提供“查看阅读手势”入口，随时手动查看；从设置查看不消耗首次进入正文的提示，也不改变进度。
- 书签和笔记暂不纳入 Demo，本轮也不扩展书内搜索、分组、统计或下载。


## 12. 完整功能布局原型 v0.3（本轮确认）

本轮范围扩大至用户提供的 47 个模块，用最少的共享界面代码验证 iOS 信息架构和操作流程，不实现真实后端。底部导航扩展为书架、发现、书源、工具、我的；阅读器和详情提供就近入口。

多源搜索、全文检索、换源、导入、不同文件类型阅读、书源管理及调试、朗读和 AI 配置、净化高亮、主题字体、标题画布、段评、备份同步、统计、文件缓存、浏览器及网络配置均提供可点击的配置或预览页面。书签按本轮新清单加入演示，笔记仍不在范围。

现有阅读、进度和收藏继续可用；新增复杂能力使用模拟结果，不把后端或规则引擎作为原型的前置工作。逐项对照与模拟边界见 `ios/FEATURES.md`，新增界面和状态集中在 `ios/Yueshan/Demo/` 的 4 个共享文件。
